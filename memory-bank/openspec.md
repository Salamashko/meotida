# OpenSpec для meotida (подготовлено, НЕ запущено)

**Статус: не установлен и не инициализирован в этом репозитории.** Запускаем только по команде
владелицы («запусти OpenSpec»). До этого не ставить пакет, не делать `openspec init`, не создавать
`openspec/`. Этот файл — справка, чтобы ничего не искать заново.
Источник: https://github.com/Fission-AI/OpenSpec/ (npm-пакет `@fission-ai/openspec`).

## Что это и зачем
Процесс «сначала спецификация, потом код». Для нетривиального изменения ИИ сначала пишет в файлах,
что меняется, почему и по каким задачам; владелица читает и правит план; только потом идёт код.
Даёт контрольную точку до кода, чек-лист `tasks.md` (не теряется при обрыве сессии) и письменный
след решений. Работает на уровне одного изменения; Memory Bank при этом хранит состояние проекта
целиком — они дополняют друг друга, не заменяют.

Для каждого изменения — папка `openspec/changes/<slug>/`:
`proposal.md` (зачем и что меняется), `specs/` (требования и сценарии), `design.md` (техрешение,
для мелких правок не нужен), `tasks.md` (чек-лист). Готовое и работающее переезжает в `openspec/archive/`.

## Когда применять
- Да: новая фича, изменение схемы БД или контракта/API, правка, затрагивающая несколько модулей,
  всё рискованное для боевого сервера.
- Нет: опечатки, мелкий рефакторинг, точечный фикс бага — без OpenSpec или через `/opsx:ff`.

## Запуск (только по команде владелицы)
Нужен Node.js ≥ 20.19.0 (`node --version`; нет или старый — сообщить и остановиться, Node самой не ставить).

```bash
# 1. Проверить среду
node --version                                          # ожидается: v20.19.0 или выше
# 2. Установить пакет (сначала показать команду владелице и дождаться «да»)
npm install -g @fission-ai/openspec@latest              # или: pnpm add -g … / bun add -g … / yarn global add … (только Yarn 1.x)
openspec --version                                      # ожидается: номер версии; «command not found» — сказать, куда встал пакет и как добавить в PATH
# 3. Инициализировать в корне репозитория
openspec init --help                                    # найти id своего ИИ-инструмента (Claude Code, Cursor, Cline, Codex, Copilot=github-copilot…)
openspec init --tools <id>                              # <id> взять из вывода предыдущей команды
# 4. Закоммитить результат (папка openspec/ и файлы интеграции — часть проекта, не в .gitignore)
git status --short
```

Правила при запуске:
- Установка идёт вне проекта — команду показать и дождаться подтверждения. Нужны sudo/права —
  остановиться и спросить. Файлы шелла (`.bashrc`, `.zshrc`, `.profile`) не править — только показать, что изменить.
- OpenSpec — инструмент разработки. На боевой сервер (`root@8314715-nw871204`) его ставить не нужно:
  он нужен там, где ИИ пишет код (сессия ассистента / компьютер владелицы).
- Перед `init` найти в проекте следы старых версий (папки `…/commands/openspec/`, блоки-маркеры
  OpenSpec в `CLAUDE.md`/`AGENTS.md`, файлы `opsx-*.md` в домашней папке), показать список и дождаться
  согласия — `init` удалит их сам.
- После `init` рассказать владелице: сколько skills/команд создано и где, есть ли пометка
  «Setup required», и **точное написание команд** для её инструмента (`/opsx:propose`,
  `/opsx-propose`, `@opsx-propose` или `$openspec-propose` — брать из созданных файлов).

## Рабочий цикл на одну фичу (slash-команды в чате с ИИ)
1. `/opsx:explore` (по желанию) — обсудить идею без обязательств, ИИ читает код.
2. `/opsx:propose <описание идеи>` — ИИ создаёт `openspec/changes/<slug>/` (proposal, specs, tasks, при необходимости design).
3. Владелица читает и правит файлы — **главная точка контроля до кода**.
4. `/opsx:apply` — ИИ выполняет `tasks.md`, отмечая прогресс.
5. `/opsx:archive` — после мёржа и проверки изменение уходит в `openspec/archive/`.

Расширенный профиль (`openspec config profile`): `/opsx:new`, `/opsx:continue`, `/opsx:ff` (быстрый режим
для мелочей), `/opsx:verify` (код соответствует спеке?), `/opsx:bulk-archive`, `/opsx:onboard`.

## CLI в терминале
```bash
openspec list                 # активные изменения
openspec show <id>            # детали изменения или спеки
openspec update               # обновить интеграцию после апдейта пакета (в каждом репо отдельно)
npm install -g @fission-ai/openspec@latest   # обновить сам пакет
```

## Связка с Memory Bank (после запуска)
1. В `activeContext.md` вести раздел «Активные изменения (OpenSpec)»: какие `openspec/changes/*`
   в работе и в каком статусе.
2. После `/opsx:archive` — обновить `progress.md`; если решение архитектурное — `systemPatterns.md` / `techContext.md`.
3. Порядок чтения в начале сессии: весь `memory-bank/`, затем (если задача про конкретную фичу) нужная
   папка в `openspec/changes/` или `openspec/archive/`.
4. Пройти один полный цикл `propose → apply → archive` на мелкой реальной задаче и проверить, что
   `progress.md` и `activeContext.md` обновились.
